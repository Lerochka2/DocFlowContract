# Проверка классификатора документов

Модель `tfidf-logreg-v2` по-прежнему использует TF-IDF и логистическую регрессию. Основная доработка — 40 дополнительных длинных учебных примеров соглашений об изменении условий договора. Это помогает отличать их от основного договора, когда в тексте много слов «договор», «поставка», «стороны». Данные из пользовательских PDF при обучении не использовались.

## Независимая локальная проверка

В `storage` обнаружено 66 PDF. Один PDF не содержал встроенного текста, поэтому он не вошёл в проверку классификатора. Остальные 65 файлов дали 36 различных извлечённых текстов. Каждому отличающемуся тексту вручную присвоена одна из четырёх меток или `OTHER` для документа вне этих типов. В `data/classifier_eval_manifest.csv` сохранены только SHA-256 хеши текста и метки, сами документы в Git не добавлены. Скрипт `python -B -m scripts.evaluate_classifier` удаляет повторы и сравнивает модель с этой разметкой.

| Показатель | Прежняя модель | Новая модель |
| --- | ---: | ---: |
| Правильный тип среди 29 документов известных типов | 22 | 28 |
| Автоматически принятые известные документы | 4 | 3 |
| Ошибочно автоматически принятые известные документы | 0 | 0 |
| Автоматически принятые документы `OTHER` (из 7) | 0 | 0 |

Оставшаяся ошибка новой модели — одно соглашение об изменении условий, названное договором с уверенностью около 0,32. Порог автоматического принятия равен 0,8, поэтому такой результат остаётся на ручной проверке. Автоматическое принятие стало немного реже; порог не снижали ради показателя покрытия.

Внутреннее случайное разделение сгенерированных текстов при обучении показало точность 100% на 104 примерах. Эта цифра **не оценивает качество на новых формах документов**: обучающие и проверочные тексты используют одни и те же шаблоны. Локальные 36 разных PDF тоже небольшая выборка, в ней только одно приложение и мало соглашений о продлении. Результаты полезны для проверки исправленной ошибки, но не доказывают точность на любых реальных документах. Для более надёжной оценки нужны дополнительные размеченные PDF каждого типа, собранные отдельно от обучающих шаблонов.

OCR проверяется отдельно на настоящем PDF-скане русского договора: извлечённый текст передаётся тому же классификатору. Документы без читаемого текста и неполное OCR остаются на ручной проверке.
